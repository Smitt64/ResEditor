# Бинарный формат ресурса меню (RES_MENU / RES_MENU2)

## Общая структура

Тело ресурса, которое видит `ResBuffer` после чтения ресурсного заголовка:

| Смещение | Размер | Тип | Описание |
|---|---|---|---|
| 0 | 1 | `uint8` | длина комментария (`len`) |
| 1 | `len` | байты | текст комментария в кодировке IBM 866 |
| 1 + len | 2 | `uint16` | общее количество структур `MENU` в ресурсе (`nitems`) |
| 3 + len | 2 | `uint16` | общий размер пула строк (`nameLens`) |

Далее следует рекурсивный блок popup'а — описание корневого меню.

## Блок popup'а

| Поле | Тип | Описание |
|---|---|---|
| `nItem` | `uint16` | количество пунктов в данном popup'е |

Затем для каждого пункта:

| Поле | Тип | Описание |
|---|---|---|
| `tp` | `int16` | тип: `RES_MITEM` (1), `RES_MPOPUP` (2) или `RES_DELIM` (3) |

### Обычный пункт (`RES_MITEM`)

| Поле | Тип | Описание |
|---|---|---|
| `Help` | `uint16` | идентификатор страницы помощи |
| `name` | строка с префиксом-длиной | заголовок пункта |
| `par` | строка с префиксом-длиной | статусная/параметрическая строка |
| `x` | `uint16` | код команды |

Если версия ресурса `>= 2`, далее следуют три поля `uint32`:

| Поле | Описание |
|---|---|
| `cmdEx` | расширенные флаги команды (Alt/Shift/Ctrl и т.п.) |
| `iconID` | идентификатор иконки на панели инструментов |
| `flags` | битовые флаги `dFMENU_*` |

### Подменю (`RES_MPOPUP`)

Содержит те же поля `Help`, `name`, `par`, что и обычный пункт, после которых рекурсивно располагается блок popup'а с пунктами подменю.

### Разделитель (`RES_DELIM`)

Дополнительных данных не содержит.

## Кодирование строк

Каждая строка хранится как:
1. `int16` — длина (`len`).
2. `len` байт текста в кодировке IBM 866.

Для декодирования используется `ResBuffer::decodeString()`.

## Запись (сохранение)

Запись реализована в `EditorMenuBar::writeMenu()` / `writePopUp()` /
`WriteString()` (зеркально `setMenu()` / `readPopUp()` / `ReadString()`) и
вызывается из `MenuEditorWindow::save()`:

- тело всегда пишется в **версии 2** (`res->setResVersion(2)`), поэтому поля
  `cmdEx`/`iconID`/`flags` присутствуют у каждого пункта;
- комментарий пишется и в тело (`uint8` длины + байты IBM866, максимум 255
  байт), и в заголовок ресурса (`res->setComment()`);
- `nitems` — общее число структур `MENU` (пункты + подменю + разделители
  на всех уровнях); `nameLens` — размер пула строк рантайма: для каждого
  не-разделителя `(длина name + 1) + (длина par + 1)` (каждая строка в пуле
  занимает `len` байт + завершающий `'\0'`);
- имя пункта формируется как `encodeMnemonic(text)` плюс, при непустом
  `QAction::shortcut()`, `'\t'` + сочетание в `QKeySequence::PortableText`
  (зеркально `decodeMnemonic`/`extractShortcut`: табуляция — первый
  приоритет разбора, round-trip точный). Если исходное имя пункта не
  содержало текста сочетания, но оно выводится из `commandId`, при
  сохранении сочетание дописывается в имя — так же делал и старый редактор;
- `flags` пишется целиком (`m_flags`), включая бит `DISINEMPTYSCROL`;
- `helpId` и `commandId` проверяются на вхождение в `uint16` — при
  переполнении сохранение прерывается с ошибкой.

## Соответствие модели Qt

| Элемент ресурса | Виджет Qt |
|---|---|
| popup | `EditorMenu` |
| `RES_MITEM` | `MenuAction` |
| `RES_DELIM` | `MenuAction` с `setSeparator(true)` |
| `par` | `statusTip` / `toolTip` |
| `Help` | `helpId` (`Q_PROPERTY` в `EditorMenu` / `MenuAction`) |
| `x` | `commandId` (`Q_PROPERTY` в `MenuAction`) |
| `cmdEx` | `cmdEx` (`Q_PROPERTY` в `MenuAction`) |
| `iconID` | `iconID` (`Q_PROPERTY` в `MenuAction`) |
| `flags` | `actionFlags` (`Q_PROPERTY` в `MenuAction`, `MenuAction::ActionFlags`) |

## Флаги `dFMENU_*`

Поле `flags` интерпретируется как битовая маска. В `MenuAction` для него
создан тип `MenuAction::ActionFlags` (`QFlags<MenuAction::ActionFlag>`) со значениями:

| Константа | Значение | Описание |
|---|---|---|
| `MenuAction::ActionFlag::Toolbar` | `0x00000001` | пункт попадает на ToolBar (`dFMENU_TOOLBAR`) |
| `MenuAction::ActionFlag::Context` | `0x00000002` | пункт попадает в контекстное меню (`dFMENU_CONTEXT`) |
| `MenuAction::FlagDisabledInEmptyScroll` | `0x00000004` | пункт недоступен в пустом скроллинге (`DISINEMPTYSCROL`) |

Бит `DISINEMPTYSCROL` редактируется отдельным bool-свойством
`disabledInEmptyScroll`, которое устанавливает/сбрасывает бит в общем
поле `flags` (`m_flags`). При изменении флага через `actionFlags`
сигнал `disabledInEmptyScrollChanged` испускается, если бит изменился.

## Мнемоника (подчёркивание буквы)

Заголовки пунктов и подменю в старом формате обрамляют подчёркнутую букву тильдами:
`~Д~ействия`. При загрузке такая пара `~X~` преобразуется в Qt-формат `&X`,
то есть `~Д~ействия` → `&Действия`.

В современных стилях Qt подчёркивание у мнемоник по умолчанию скрыто и
появляется только при нажатии `Alt`. В редакторе меню оно форсируется через
`QProxyStyle` (`SH_UnderlineShortcut`), чтобы выглядеть как в старом
приложении.

## Сочетания клавиш

Если в наименовании пункта после символа табуляции указано сочетание клавиш,
например `Действия\tCtrl+D`, оно выделяется и преобразуется в `QKeySequence`
через `QAction::setShortcut()`. Поддерживается также старое выравнивание
несколькими пробелами: `Действия    Ctrl+D`. Старые ресурсы могут
использовать дефис (`Ctrl-D`) — он нормализуется в `Ctrl+D` перед разбором.
